## 6. 状态派生规则（阶段 ← 子任务）

为避免“阶段标题状态”与“子任务状态”不一致，阶段状态必须从该阶段所有子任务状态派生：

1. 任一子任务为 `[!]` → 阶段为 `[!]`
2. 否则，任一子任务为 `[待验证]` → 阶段为 `[待验证]`
3. 否则，任一子任务为 `[~]` → 阶段为 `[~]`
4. 否则，所有子任务为 `[x]` 或 `[-]` → 阶段为 `[x]`
5. 其他情况 → 阶段为 `[ ]`

## 7. 状态更新时机（主 agent 维护）

主 agent 更新本文件状态的时机如下（子 agent 不直接改本文件）：

- 派发子 agent 前：把对应子任务状态改为 `[~]`。
- 编码类子任务完成返回后：把对应子任务状态改为 `[待验证]`，并触发 `y1n-code-reviewer`。
- code review 通过后：把对应子任务状态改为 `[x]`。
- code review 发现阻塞问题：把对应子任务状态改为 `[!]`，并在“完成说明”里记录问题摘要与回环策略。
- 用户同意跳过：把对应子任务或阶段改为 `[-]`，并记录原因与影响。

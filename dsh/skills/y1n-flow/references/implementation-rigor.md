# 实现严谨性规范

以下规则适用于所有语言，在编码和审查时必须遵循。

## 1. 快速失败与显式意图

- **禁止静默回退**：不使用回退逻辑，尤其是脚本中。配置不足时应中止并打印清晰反馈。错误被隐藏的地方，复杂度就会增长。
- **显式 > 默认**：避免任意默认值。要求用户显式表达意图。用结构化、简洁、因果性的注释记录理由，确保接口清晰。

## 2. 配置优先级

- **配置文件优先**：优先使用结构化配置文件（YAML、TOML 等），而非环境变量或命令行参数，除非用户明确要求。
- **最少 ENV**：除非容器化场景必须，否则避免环境变量。
- **CLI 保持简洁**：CLI 只保留 `--config/-c` 和 `--workdir/-w` 等少量必要参数。复杂配置必须放在配置文件中。

## 3. 收敛（反发散）

- **枚举 > 字符串**：用类型防止状态发散。
- **全局常量 > 硬编码**：集中管理重复值，防止"潜在发散"——即需要在多处同步修改的场景。
- **统一词汇**：一个概念，一个名字。
  - 示例：`XXXActor` 表示独占后台实体；`XXXHandle` 表示其句柄。
